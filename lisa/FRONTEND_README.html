    LISA Frontend

    React + TypeScript frontend for the LISA Instructor Compliance Dashboard. Built with Vite.

    Setup

    npm install

    Copy ../.env.example or set VITE_API_BASE in a .env file:

    VITE_API_BASE=http://localhost:5001/api

    In development, Vite proxies /api requests to the Flask backend so session cookies stay on the same origin. In production, Flask serves the compiled dist/ directly and no proxy is needed.

    Running

    # Development (Vite dev server on port 5173)
npm run dev

# Production build (output to dist/)
npm run build

    Both the backend and frontend dev servers can be started together from the repo root with lisa_backend/scripts/launch_dev.sh.

    Project Structure

    lisa_frontend/src/

    Views

    The dashboard has six views, toggled by tab buttons at the top:

    Grading Compliance — lists instructors with counts of overdue ungraded submissions. Clicking a row expands per-course detail; clicking a course opens the full submissions table for that course.

    Discussion Response Compliance — lists instructors with their discussion response rates. Response rates are calculated per-discussion topic. Clicking a row expands per-course detail; clicking a course opens the discussion responses table.

    Announcements — lists instructors with total announcement counts and scheduled announcement counts per course.

    Rubric Compliance — lists instructors with how well they use rubrics when grading: graded submissions on rubric assignments, submissions graded without the rubric, rubric lines graded out of the total (and as a percentage), ungraded lines, rubric line comments, instructor submission comments, and submissions with no feedback at all. Counts are per course, so every active teacher on a course gets that course's totals, and only graded submissions count. Clicking a row expands per-course detail; "View Submissions" opens the per-submission table for that course, where each row links to the submission in SpeedGrader. It uses the same dashboard filter bar and App-level filters (name, term, date range, CE toggle, title list) as the grading view, and the submissions table gets the same filters, so its counts match the row it was opened from. Flags raised from this view are recorded as grading flags, so they show up as grading flags in the Flags view and in the Grading view's flag counts.

    Flags — lists all recorded instructor flags (violations). Each row shows flag type (grading, discussions, announcements, other), term, date, and optional reason note. Flags can be edited or deleted inline. Filterable by term, instructor ID, flag type, reason text, and date range.

    Grade Distribution — lists per-assignment grade distribution statistics (mean, median, mode, sample standard deviation, min/max percentage and raw scores) aggregated across all sections sharing an assignment template (via master_courses_child_subscriptions). Filterable by term, course code, and assignment title, with an option to group by individual section instead of merging them. Sortable and paginated like the other views, but has no flag column and uses its own term/course-code/title filters instead of the shared dashboard filter bar.

    The Grading, Discussion, Announcements and Rubric Compliance views each include a flag column showing the instructor's current-term flag count and total lifetime flag count. Clicking the flag button opens a dialog to record a new flag. They share the same filter controls: instructor name search, date range, term selector, and CE toggle. Picking a term resets the date range to that term's dates, since the grading, discussion, rubric and conversation endpoints reject dates outside the term. "View Submissions" sends the same dates, CE toggle and title filter as the grading counts it was opened from.

    Instructor names are rendered as mailto links. Email addresses are derived from the instructor's name (first initial + last name + @unity.edu) because the canvas database does not store email addresses.

    Links are set to open in new tab by default (<base target="_blank" />) in index.html

    State

    Each table component owns its filter bar, pagination (usePaginatedTable) and CSV export, and fetches its first page when it mounts. App.tsx holds only what is shared: auth, the view toggle, violation counts, and the dashboard filters (name, term, date range, CE, gallery, title list) used by the grading, discussion, announcement, conversation and rubric tables, so those filters carry over between tabs. Editing a filter shows "Filters changed — click Go to apply"; Go (or Enter in a text filter) fetches page 1 with the new filters, and Prev/Next paginate the current result.

    The backend owns the defaults: a table's first fetch sends no sort, term or page size, and the table follows the sort_column/sort_direction/page_size echoed in each response. The CE Only checkbox default, the default excluded assignment titles and the Canvas link prefix come from the backend's /api/config (see src/config.ts), and the current term from /api/current_term, so the frontend .env files only hold hosting paths (VITE_BASE_PATH, VITE_API_BASE). No constants file is shared with the backend.

    When a fetch fails, the table keeps its rows and the pagination bar shows the backend's error message (e.g. dates outside the selected term). "Export CSV" fetches every row in the current sort: it asks for them all in one page and then fetches whatever pages the backend's page-size cap left over.

    Switching tabs remounts the table, so it refetches. Opening a detail page (submissions, discussion responses, a conversation, rubric submissions) only hides the dashboard, so returning keeps the table's page and sort.

    Syncing state is polled every 10 seconds after a manual sync is triggered, and the instructor data is automatically refreshed when the sync completes.
