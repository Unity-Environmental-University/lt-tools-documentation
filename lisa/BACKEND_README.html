    LISA Backend

    Flask API server for the LISA Instructor Compliance Dashboard. Pulls Canvas LMS data via the Instructure DAP client, stores it in PostgreSQL, and serves compliance metrics to the frontend.

    Prerequisites

    • Python 3.12 (required by scripts; 3.11+ is the minimum per DAP client docs)
    • Linux environment — the instructure-dap-client package requires linux-based Python. On Windows, run inside WSL.
    • PostgreSQL running and accessible (see Docker setup repo linked in the root README)
    • Node.js / npm — only needed if running the full dev stack via launch_dev.sh

    Setup

    1. Create and populate .env

    Copy env.example to .env and fill in all values. See Environment Variables below.

    2. Install dependencies

    uv sync

    3. Initialize the database

    The PostgreSQL database must already exist and be running. To populate it with Canvas data for the first time:

    source .venv/bin/activate
python3.12 operate_db.py init all

    This pulls all tracked tables from Canvas DAP into the database. It may take a while on first run.

    Running

    Development

    From the repo root, scripts/launch_dev.sh starts both the Flask backend (port 5001) and the Vite frontend dev server in one step:

    bash lisa_backend/scripts/launch_dev.sh

    The frontend dev server proxies /api requests to the Flask process, keeping session cookies on the same origin. Note: the backend does not auto-reload on file changes (use_reloader=False) — restart it manually after edits.

    To run just the backend:

    export FLASK_ENV=development
uv run python3.12 api_server.py

    Production

    scripts/launch_prod.sh starts the Waitress WSGI server on port 5000 and automatically restarts it on non-zero exits:

    bash lisa_backend/scripts/launch_prod.sh

    In production, Flask also serves the compiled frontend from ../lisa_frontend/dist/. Build the frontend before starting the server:

    cd ../lisa_frontend && npm run build

    On unitycanvas-tcc, this script is launched automatically at startup via Windows Task Scheduler.

    Database Sync

    Canvas data is kept current by syncing with the DAP API. The sync script waits for PostgreSQL to be ready before running:

    bash lisa_backend/scripts/run_sync.sh

    This calls python3.12 operate_db.py sync all under the hood. On the production server, a cron job runs this script twice daily.

    You can also trigger a sync at any time from the UI, or invoke operate_db.py directly:

    # Sync all tables
python3.12 operate_db.py sync all

# Sync specific tables
python3.12 operate_db.py sync submissions,assignments

# Initialize (first-time load) specific tables
python3.12 operate_db.py init enrollments,courses

    Tracked tables: users, courses, enrollment_terms, assignments, submissions, enrollments, content_tags, context_modules, discussion_entries, discussion_topics, discussion_entry_participants, master_courses_child_subscriptions, submission_comments

    submission_comments was added for the Rubric Compliance view. An existing database needs a one-time python3.12 operate_db.py init submission_comments followed by an API restart (the table is looked up when it is first needed, so the other endpoints keep working until then). Run the init when deploying this change: until then the nightly sync all reports a failure for submission_comments and exits non-zero, although the other tables still sync.

    Database Indexes

    The following partial indexes exist on the canvas schema to support compliance queries. They are partial (i.e. indexed over a filtered subset of rows) because every query that joins on these tables always includes the filter condition — inactive/deleted rows are never needed. Partial indexes are smaller and faster than full indexes on the same columns since PostgreSQL only indexes the rows that queries actually touch.

    submissions - idx_submissions_course_user_active — btree on (course_id, user_id) where workflow_state NOT IN ('unsubmitted', 'deleted')

    enrollments - idx_enrollments_course_user_active — btree on (course_id, user_id) where workflow_state = 'active' - idx_enrollments_teacher_active — btree on (user_id, course_id) where workflow_state = 'active' AND type = 'TeacherEnrollment'

    courses - idx_courses_term_id — btree on (enrollment_term_id)

    Suggested indexes

    These would support the rubric compliance queries but are not created automatically; create them manually if the rubric endpoints are slow.

    rubric_assessments - idx_rubric_assessments_submission_grading — btree on (artifact_id) where artifact_type = 'Submission' AND assessment_type = 'grading'

    submission_comments - idx_submission_comments_submission — btree on (submission_id)

    rubric_associations - idx_rubric_associations_assignment_active — btree on (association_id) where association_type = 'Assignment' AND workflow_state = 'active'

    Environment Variables

    Copy env.example to .env. All variables below are required for production.

    Variable Description
    DAP_CLIENT_ID Instructure DAP API client ID
    DAP_CLIENT_SECRET Instructure DAP API client secret
    DAP_API_URL Instructure DAP API endpoint URL
    LISA_CANVAS_DB_NAME PostgreSQL database name
    LISA_CANVAS_DB_USER PostgreSQL username
    LISA_CANVAS_DB_PASSWORD PostgreSQL password
    LISA_CANVAS_DB_HOST PostgreSQL host (typically localhost)
    LISA_CANVAS_DB_PORT PostgreSQL port
    FLASK_ENV development or production
    FLASK_SECRET_KEY Secret key for Flask session encryption
    LDAP_SERVER LDAP server URL (e.g. ldaps://subdomain.domain.com)
    LDAP_BASE_DN Base DN for LDAP user searches
    LDAP_REQUIRED_GROUP Full CN of the AD group required for access
    IS_CE true for the CE deployment (optional, default false)
    CANVAS_BASE_URL Canvas instance the data comes from (optional)
    DEFAULT_TERM_ID Term used when a request names no term_id, and by /api/current_term when no term is running, e.g. between terms (optional; unset means term_id is required)
    OVERDUE_HOURS_DEFAULT / OVERDUE_HOURS_CE Hours before an ungraded submission is overdue (optional, default 72 / 48)

    Security note: In production (FLASK_ENV=production), SESSION_COOKIE_SECURE is set to True, ensuring session cookies are only sent over HTTPS.

    API Endpoints

    All endpoints are prefixed with /api. All except health and login require an active session: a dashboard (LDAP) session, except /api/search-* (Canvas session) and /api/terms (either).

    Method Endpoint Description
    GET /api/health Server health and version info
    POST /api/login Authenticate with campus LDAP credentials
    POST /api/logout Clear session
    GET /api/me Current logged-in username
    GET /api/config Deployment settings for the dashboard (is_CE default, canvas_courses_url for links, default excluded_assignment_titles)
    GET /api/terms All terms, newest first, with start_at/end_at as YYYY-MM-DD Eastern dates
    GET /api/current_term Current UG/grad term (?isUnderGrad=true/false), else DEFAULT_TERM_ID's term; 404 if neither
    GET /api/dashboard/instructors Paginated grading compliance data per instructor
    GET /api/dashboard/discussion-instructors Paginated discussion response compliance data per instructor
    GET /api/dashboard/announcement-instructors Paginated announcement compliance data per instructor
    GET /api/dashboard/rubric-instructors Paginated rubric compliance data per instructor
    GET /api/grade-distribution Paginated per-assignment grade distribution stats for a term
    GET /api/instructor_conversations Paginated conversation stats per instructor (term_id, start_date, end_date, instructor_name; with a term_id, only that term's teachers and dates within it)
    GET /api/CALM_completion Paginated CALM module progress per student
    GET /api/CE-badge-grading Paginated CE badge grading per instructor and course in a term
    GET /api/search-* Paginated phrase search over syllabi, assignments, pages, topics, topic-replies, filenames, quizzes and questions
    GET /api/courses/<id>/submissions Submissions for a specific course
    GET /api/courses/<id>/rubric-submissions Graded rubric submissions for a specific course, with per-submission rubric line and comment counts
    GET /api/discussions/<id>/responses Discussion responses for a specific discussion
    POST /api/sync_request Trigger a Canvas DAP sync (async, returns 202)
    GET /api/last_sync Timestamp of last successful sync
    GET /api/violations List all flags, optionally filtered by flag_term_id, flag_type, instructor_id
    POST /api/violations Create a new flag (instructor_id, flag_type, flag_term_id required; reason_for_flag optional)
    GET /api/violations/<id> Get a single flag by ID
    PUT /api/violations/<id> Update flag type and/or reason
    DELETE /api/violations/<id> Delete a flag
    GET /api/violations/counts Per-instructor flag counts for a given term (flag_term_id required)

    Every query param is optional except where marked required; leave a param out to get the endpoint's default. The shared parsing lives in utils/api_helpers.py:

    • Paging and sorting (every paginated endpoint): page, page_size (capped at MAX_PAGE_SIZE), sort_column, sort_direction. Any column in the result can be sorted on except JSON/array ones; an unknown sort_column or sort_direction falls back to the default. Paginated responses echo the sort that was applied as pagination.sort_column and pagination.sort_direction (used for the sort arrows), and the page_size that was used.
    • Term: term_id, defaulting to DEFAULT_TERM_ID (a 400 if neither is set). The frontend always sends the term it got from /api/current_term. The dashboard endpoints echo it as pagination.term_id. Conversations is the exception: with no term_id it covers every teacher.
    • Dates: start_date, end_date as YYYY-MM-DD, read as Eastern day bounds. A malformed date or a start after the end is a 400 with an error message. The grading, discussion and rubric instructor endpoints also reject dates outside the selected term, and so does conversations when a term_id is given.
    • Title filter: repeatable title_filter plus title_filter_mode (blacklist (default) or whitelist).

    Instructor/discussion/announcement endpoint query params: paging and sorting, term_id, name, start_date, end_date, is_CE (defaults to the deployment's IS_CE). Instructors also take the title filter and overdue_hours (defaults to OVERDUE_HOURS_DEFAULT/OVERDUE_HOURS_CE); discussions take include_gallery.

    Rubric instructor endpoint query params: paging and sorting (default graded_lines_pct ascending), term_id, name, start_date, end_date, is_CE and the title filter. The same params as the instructors endpoint minus overdue_hours. Each row has instructor_id, instructor_name, courses_this_term, the term totals rubric_submissions_term, rubric_unused_term, total_lines_term, graded_lines_term, graded_lines_pct (null when there are no lines), line_comments_pct (percent of total_lines_term, null when there are no lines), rubric_unused_pct and no_feedback_pct (percent of rubric_submissions_term, null when there are none), line_comments_term, submission_comments_term, no_feedback_term, and courses: one object per course with its course_id and rubric_submissions, rubric_unused, total_lines, graded_lines, line_comments, submission_comments and no_feedback, ordered by graded_lines ascending (all zero when the course has no rubric submissions).

    Rubric submissions endpoint query params: paging and sorting (default graded_lines ascending, then submission_id), start_date, end_date, is_CE and the title filter. The dashboard sends the same values it used for the rubric instructor counts. Each row has submission_id, course_id, assignment_id, title, student_id, student_name, graded_at, cached_due_date, rubric_used, total_lines, graded_lines, line_comments and submission_comments.

    Grade distribution endpoint query params: paging and sorting, term_id, course_code, title_filter (a single substring), group_by_section

    Submissions endpoint query params: paging and sorting, start_date, end_date, is_CE and the title filter. The dashboard sends the same values it used for the grading counts.

    Search endpoint query params: phrase (required), paging and sorting, course_name, term_id (no default: all terms), repeatable course_ids. Every result has course_id, course_name, term_id, id, title, workflow_state, created_at, updated_at and resource_link, plus type-specific columns. HTML tags are stripped before matching, so formatting doesn't split a phrase, and %/_ in the phrase match literally.

    Violations list query params: flag_term_id, flag_type, instructor_id

    Compliance Logic

    The core metric calculation lives in services/compliance_service.py. The key concept:

    • A submission is overdue if it has been sitting ungraded past the compliance window.
    • The window is 72 hours for standard courses and 48 hours for CE courses by default (OVERDUE_HOURS_DEFAULT/OVERDUE_HOURS_CE, or overdue_hours per request).
    • The window starts from the due date for on-time student submissions, or from the submission timestamp for late student submissions.

    These thresholds are applied in get_compliance_for_courses(), which returns per-course counts that api_server.py aggregates per instructor.

    Values that change per deployment (Canvas base URL, CE mode (IS_CE env var), search access role, DAP namespace, term name patterns, course code regex patterns, overdue thresholds, default excluded assignment titles and the fallback term) live in utils/config.py. Pagination defaults and default sort columns/directions are in utils/constants.py. Nothing is shared with the frontend by file: values it needs come from /api/config.

    Rubric compliance

    Rubric compliance checks whether instructors fill out rubric lines and leave comments when grading. Like grading, it is course-level: every active teacher on a course is credited with that course's totals.

    • A submission counts if it passes the same filters as the grading view (dates on cached_due_date, CE mode, title filter, active student enrollment), its workflow_state is graded, and its assignment has an active grading rubric (a rubric_associations row with association_type = 'Assignment', purpose = 'grading', workflow_state = 'active') or the submission has a grading rubric assessment. A student with more than one active enrollment in the course (e.g. two sections) is counted once per submission.
    • The submission's rubric assessment is its most recently updated rubric_assessments row with artifact_type = 'Submission' and assessment_type = 'grading' (peer review and invited assessments are ignored). Its rubric is the assessment's rubric, or the assignment's rubric when there is no assessment.
    • rubric_used — a rubric assessment exists. Grading without opening the rubric leaves no assessment. Per course, rubric_submissions counts the submissions in scope and rubric_unused those without an assessment.
    • total_lines — the number of criteria in the rubric's data. If the rubric's data can't be read, the number of entries in the assessment instead (0 with no assessment).
    • graded_lines — assessment entries whose points is not null, capped at total_lines (so a rubric edited after grading can't push it past the total). 0 with no assessment. A rating named "blank" is still a chosen rating.
    • line_comments — assessment entries with a non-blank comments.
    • submission_comments — submission_comments rows on the submission that aren't drafts or peer review comments (assessment_request_id is null) and whose author has an active TeacherEnrollment in the course (TAs don't count).
    • no_feedback — a submission with no line comments and no submission comments.

    The rubric and assessment data columns are JSON stored as text. They are parsed in Python rather than SQL (so the queries also run on the SQLite tests), and malformed or missing JSON counts as no entries. get_rubric_submissions() builds the per-submission query, get_rubric_criteria_counts() counts the criteria of the courses' rubrics, get_rubric_submission_stats() returns the per-submission counts for the drill-down, and get_rubric_compliance_for_courses() streams the same rows into per-course totals that api_server.py aggregates per instructor.

    Key Dependencies

    Package Purpose
    flask Web framework
    waitress Production WSGI server
    sqlalchemy ORM and database reflection
    psycopg2-binary PostgreSQL adapter
    instructure-dap-client Canvas DAP data sync
    ldap3 LDAP/Active Directory authentication
    python-dotenv .env file loading
    flask-cors CORS headers (development only)

    To add or update dependencies, edit pyproject.toml then run:

    uv sync

    Tests

    uv run pytest

    Tests live in tests/ and use an in-memory SQLite database — no credentials or running PostgreSQL required. regexp_replace and concat are registered on the SQLite connection so the search queries can run.

    What's covered:

    • get_term_info — correct id→name mapping, empty table
    • get_current_term — UG vs grad selection (DE5W/DE8W), excludes "test" terms, excludes expired terms, overlapping terms
    • get_term — correct lookup, nonexistent term
    • get_submissions_to_courses — workflow state filtering (unsubmitted/deleted excluded), excluded assignment titles (Introductions, Integrity 1 & 2), CE vs non-CE due date requirement, start/end date filtering, inactive enrollment exclusion, course ID scoping
    • get_compliance_for_courses — on-time overdue, late overdue, graded not counted as overdue, within-window not counted, 48h vs 72h threshold, multi-course grouping, CE mode column differences, date range propagation
    • _rubric_line_stats — all/partial/null points, whitespace-only comments, bad or missing assessment JSON, unreadable rubric falling back to the assessment's entry count, graded lines capped at the total
    • get_rubric_submission_stats — fully assessed submission with comments, graded without the rubric (rubric_used false, total from the rubric), ungraded submissions and assignments without a rubric excluded, peer review assessments ignored, latest of two grading assessments wins, student/draft/peer review comments not counted, a teacher with two enrollments counted once, a teacher of another course not counted, inactive associations excluded, an assessment without an association still counted, unreadable rubric data falling back, a student in two sections counted once
    • get_rubric_criteria_counts — criteria counted per rubric, limited to the given courses' rubrics
    • get_rubric_compliance_for_courses — per-course aggregation, courses without rubric submissions absent
    • craft_instructors_courses_query — query construction (execution requires PostgreSQL due to array_agg and regex ~ operator)
    • search_* — phrases split by HTML, literal %/_, case and whitespace, course/term filters, the standard result columns
    • utils/api_helpers — page/sort parsing and clamping, date validation (incl. term bounds), title filter, paginate_query/paginate_list ordering and paging, cached, json_errors
