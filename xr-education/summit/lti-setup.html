    Setting up the Canvas LTI tool

    Step by step, from no setup to a student finishing a Storyline course in a Canvas dev course with the score in the gradebook. Production Summit is https://ai2.unity.edu/summit; replace it if you deploy elsewhere. For how the tool works and what it stores, see SCORM courses and Canvas LTI.

    Who does what:

    Step Who
    1 to 3: secrets, deploy, check Whoever runs the Summit deploy (Infisical access)
    4: developer key A Canvas admin
    5 to 7: client id, install, place a course Summit deployer, then a teacher or designer in the dev course
    8: test as a student Anyone with Student View in the dev course

    1. Generate the secrets

    On any machine with Node 20 and this repository:

    cd dashboard
npm run learning:keys
openssl rand -hex 32   # the learning database password

    learning:keys prints four values: LEARNING_PSEUDONYM_KEY, LEARNING_VAULT_KEY, LEARNING_TOKEN_SECRET and LTI_TOOL_PRIVATE_KEY. Put them straight into Infisical and don't leave copies elsewhere. Generate them once per environment:

    • A new LEARNING_PSEUDONYM_KEY gives every returning student a new pseudonym, which splits their history.
    • Losing LEARNING_VAULT_KEY means grades can no longer be sent for students already in the database.
    • A new LTI_TOOL_PRIVATE_KEY is picked up by Canvas from /lti/jwks, so it can be rotated, but not mid-launch.

    2. Add them to Infisical

    Project: the Summit project. Environment: prod. Path: /summit. This is where webhook/deploy_summit.sh reads secrets from before it runs docker compose up -d --build.

    Required now:

    Secret Value
    COMPOSE_PROFILES learning. Starts the separate learning database. Without it, the database container doesn't start.
    LEARNING_DB_PASSWORD The openssl rand -hex 32 value.
    LEARNING_DATABASE_URL postgresql://summit_learning:<LEARNING_DB_PASSWORD>@summit-learning-db:5432/summit_learning, with the password pasted in. Setting this turns the feature on.
    LEARNING_PSEUDONYM_KEY From learning:keys.
    LEARNING_VAULT_KEY From learning:keys.
    LEARNING_TOKEN_SECRET From learning:keys.
    LTI_TOOL_PRIVATE_KEY From learning:keys: the whole value between the quotes, on one line with its literal \n escapes. Don't include the quotes.
    SUMMIT_PUBLIC_URL https://ai2.unity.edu/summit. No trailing slash.

    Required after step 4:

    Secret Value
    LTI_CLIENT_ID The Canvas developer key's client id, a long number such as 10000000000123.

    Only if they apply:

    Secret When Value
    LTI_PLATFORM_ISSUER Testing on Unity's Canvas test or beta instance instead of production https://canvas.test.instructure.com or https://canvas.beta.instructure.com. Production Canvas, including a dev course in it, needs nothing (default https://canvas.instructure.com).
    LTI_DEPLOYMENT_IDS To accept launches only from specific installs The deployment id shown when the app is installed, comma-separated. Empty accepts any install of the key.
    LTI_FRAME_ANCESTORS Canvas is reached on a custom domain rather than *.instructure.com 'self' https://canvas.unity.edu (with the real domain).
    LEARNING_CAPTURE_FREE_TEXT To keep typed free-text answers (off by default, since they can identify a student) 1
    LEARNING_MAX_PACKAGE_MB Course zips over 1 GB A number in MB

    Never set in production: LEARNING_DEMO_MODE (lets anyone play courses as made-up learners).

    None of these secrets go into git, .env.example or the Canvas developer key. Canvas only ever sees the public half of the tool key, at /lti/jwks.

    3. Deploy and check

    1. Deploy this branch the usual way (merge to docker, or run the deploy script). The app applies the learning database migrations on start.
    2. If the reverse proxy in front of Summit limits request size, raise it for /summit/api/learning/packages so course zips can be uploaded. For nginx: client_max_body_size 1024m;.
    3. Sign in to Summit as an admin and open Learning, Canvas. Everything under Ready for Canvas? should read Ready except the Canvas developer key, which needs LTI_CLIENT_ID.
    4. Open https://ai2.unity.edu/summit/lti/config and https://ai2.unity.edu/summit/lti/jwks in a browser off the university network (a phone on cellular works). Both must return JSON. Canvas fetches them from the internet.
    5. To let a non-admin account see learning data: Settings, Accounts, Allow learning data.

    4. Canvas admin: create the developer key

    Send the Canvas admin this:

    In Canvas: Admin, the root account, Developer Keys, + Developer Key, + LTI Key.

    • Key name: Summit learning
    • Owner email: the Summit maintainer
    • Redirect URIs: https://ai2.unity.edu/summit/lti/launch
    • Method: Enter URL
    • JSON URL: https://ai2.unity.edu/summit/lti/config

    Save, then switch the key On in the State column. Send back the number in the Details column (the client id).

    The JSON sets the privacy level to anonymous, so Canvas sends Summit no names or emails. It asks for the Assignment and Grade Services scopes, for line items and scores, so scores can go to the gradebook. Its placements are Assignment Selection and Link Selection.

    If Canvas has a test instance and you'd rather start there, create the key in the test instance instead and set LTI_PLATFORM_ISSUER (step 2). Keys don't carry between instances.

    5. Add the client id

    1. Add LTI_CLIENT_ID to Infisical and redeploy.
    2. On Learning, Canvas, select Check the connection to Canvas. All three checks should pass:
    3. Canvas signing keys: Summit can reach Canvas.
    4. Summit key set, from outside: Summit's public address serves its own key. A warning here only means the server can't reach its own public name; step 3.4 already confirmed Canvas can.
    5. Grade passback token: Canvas accepted Summit's key for this client id. If this fails, the key is off, the client id is wrong, or the key's JWK URL isn't https://ai2.unity.edu/summit/lti/jwks.

    6. Install the tool in the dev course

    In the dev course: Settings, Apps, View App Configurations, + App. Set Configuration Type to By Client ID, paste the client id and select Submit, then Install.

    If the course doesn't allow it, the Canvas admin can install it the same way in the sub-account that holds the dev course.

    7. Upload a course and place it

    1. Publish from Storyline: Publish, LMS, SCORM 2004 3rd or 4th edition, and zip the output. SCORM 1.2 and xAPI also work.
    2. Upload it: in Summit, Learning, Courses, Upload.
    3. Place it in Canvas: in the dev course, create an Assignment. Set Submission Type to External Tool, select Find, then Summit learning. Summit's course picker opens. Choose the course, select Add to Canvas, then Select. Set the points and Save & Publish.

    Summit’s course picker offers a Canvas grading setting for each assignment. Numeric score is the default. Choose Pass/fail to send full credit for an explicit pass and zero for an explicit fail, even when the package reports a separate quiz score. An attempt without a pass/fail outcome stays ungraded. In Canvas, set Display Grade as to Complete/Incomplete and use a positive points value. Summit still records the original score for analytics.

    A module item works too (Add item, External Tool, Summit learning), but without an assignment there is no gradebook column, so no score is sent.

    8. Test as a student

    1. Turn on Student View in the dev course and open the assignment. The course plays inside Canvas.
    2. Go through it and finish the quiz. Leave partway and come back to check resume.
    3. In Summit:
    4. Learning, Canvas: the launch is under Recent launches, and the assignment under Canvas assignments, with a grade sent.
    5. Learning, Overview: select the course to see slides, answers and clicks. The attempt page shows every answer and the timeline.
    6. In Canvas: the Gradebook shows the score for Test Student.

    Opening the assignment as a teacher works too, but it's recorded as an instructor try: it gets no grade and is left out of the statistics.

    Also try a blueprint sync if the dev course setup has one: place the course in a blueprint, sync it to a child course, and launch from the child. Recent launches shows whether the child came through as its own course and assignment. This shapes how Summit will group dev, blueprint and live courses.

    When it doesn't work

    Learning, Canvas, Recent launches shows each login and launch, which step failed, and why. No user ids are kept there.

    What you see Fix
    Canvas shows its own error; Summit's log has a login and no launch after it The developer key's Redirect URIs must include https://ai2.unity.edu/summit/lti/launch, and the key must be On.
    issuer ... is not LTI_PLATFORM_ISSUER The key is in a test or beta instance; set LTI_PLATFORM_ISSUER.
    client id ... is not LTI_CLIENT_ID The key was recreated; copy the new client id.
    deployment ... is not in LTI_DEPLOYMENT_IDS Add the new install's deployment id, or empty the setting.
    login state unknown, expired or already used The launch took over 10 minutes or the page was reloaded mid-launch. Open the assignment again.
    "Summit learning is not configured on this server" A required secret is missing; Ready for Canvas? names it.
    A blank frame in Canvas Canvas is on a custom domain; set LTI_FRAME_ANCESTORS.
    "Choose a package" when opening the assignment The assignment was made without the picker. Edit it, choose External Tool, find Summit learning again and pick the course.
    Score missing from the gradebook Grades that didn't reach Canvas on the Canvas tab shows Canvas's answer. Fix the cause and select Resend.

    Before real students

    These are FERPA education records. Before a live course uses this:

    • Get the registrar's sign-off on the data design (see SCORM courses and Canvas LTI).
    • Set up a backup with restricted access for the summit-learning-data volume. It is deliberately not in Summit's normal backups.
    • Decide on retention.
